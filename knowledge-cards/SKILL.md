# 知识卡片模式

本 skill 是一个**口径**，不是模板。加载它不改变你原有的教学或协作方式，只改变知识的**落地形状**：该留成条目的东西要留成自包含的单元。

一句话总纲：**卡是对话的句法，不是存储单位。**

---

## 0. 语言与呈现

- 用用户的语言输出（中文进中文出，英文进英文出），不要混排。
- **文字与公式相伴**：不要只丢符号，也不要只用模糊文字。每个符号第一次出现时用一句话说明它是什么。
- 断句清楚、结论前置；推理段落可以长，但结论必须能被单独摘出来。

---

## 1. 何时必须落卡（机械谓词，不靠临场判断）

落卡由谓词触发，不由状态或心情触发。命中任一条即**必须**产出卡片：

- 同一个对象/概念**第二次出现**；
- 出现一条**可复用的断言或结论**（能被搬到另一个问题里用的那种）；
- 一个**步骤被重复**（第二次做同一个操作）；
- 用户说"不懂 / 卡住 / 奇怪"；
- 实验结果**反直觉**（预期与观测不符）。

**不必**落卡的情形：寒暄、追问细节、纯推理过渡、澄清措辞。

粒度由你决定，**是否必须落卡由谓词决定**。这条分工同时给你可靠性和灵活性。

---

## 2. 卡不是模板，是菜单

- 一张卡最少**一个**节就能成立；节按需选，不要求齐全。
- 反面：每轮回复都摆出九个小标题——那是填表，不是卡片。填表式输出会让人停止阅读。
- 可选节（挑着用）：触发、动机、主张/定义、流程、证明、条件、边界/局限、术语、命名理由、锚点、上下层、状态、来源标记。

---

## 3. 「完整」的定义：入口自由

完整 ≠ 内容最多，而是**每一节都能单独当作进入点，节间不互相承重**。用户从任意一节读起都读得通。

排布按 **主 → 次 → 末** 递减：

| 层 | 内容 | 要求 |
|---|---|---|
| 主 | 主张、成立条件、边界 | 每轮都给，不增不减 |
| 次 | 取得路径、证明链、与邻近概念的区别、术语展开 | 按需加 |
| 末 | 命名理由、状态、在结构中的位置 | 最后给，之前可压成一行 |

因此卡**随时可停**：读到哪一层停下都成立。也可以被**单独摘走**——边要写（用于放置），但读卡不依赖任何边。**边伴随，但不承重。**

---

## 4. 每个节必须能说出「缺失故障模式」

说不出的节，删掉。故障模式是节存在的唯一理由。

| 节 | 缺失后果 |
|---|---|
| 触发 | 想不起来该用它 |
| 动机 | 不知道它为什么存在，修订时被误删 |
| 主张/定义 | 无从判定 |
| 条件 | 不知道什么时候能用 |
| 边界/局限 | **误用**——最危险的一种缺失 |
| 流程 | 无法复核，也无法迁移到别的对象 |
| 证明 | 退化成断言 |
| 术语 | 几天后读不懂流程 |
| 命名理由 | 与邻近概念混为一谈，命名空间被重复占用 |
| 锚点 | 无法回验、无法引用 |
| 上下层 | 成为孤岛，重复造卡 |
| 来源标记 | 分不清哪条能直接用、哪条必须带上前提 |

---

## 5. 式子必须标来源（核心判据之一）

任何式子都要能回答"它是怎么来的"。四类，缺一不可判：

| 类型 | 含义 | 换个模型还成立吗 |
|---|---|---|
| **恒等** | 由定义直接得到 | 成立，任何同类结构都对 |
| **约定** | 工程或建模上的选择 | 不成立——换一套选择就变 |
| **假设** | 前提条件，不是结论 | 是条件，谈不上成立与否 |
| **结论** | 以上三类齐备后推出 | 只在同一组前提下成立 |

**自检判据（很好用）：看系数是"算出来的"还是"给出来的"。**

- 系数由别处的量决定、没有自由度 → **推导结果**；
- 系数可以自由输入、用来拟合 → **主观拟合**。

### 例子（泛函分析）

- **恒等**：$\|x\|=\sqrt{\langle x,x\rangle}$——诱导范数就是这么定义的。
- **约定**：称线性算子 $T$ 有界，是指 $\exists C>0,\ \|Tx\|_Y\le C\|x\|_X$。这是"有界"一词的**定义**，不是定理；它与"值域有界"不是一回事。
- **假设**：$\mathcal H$ 完备（Hilbert 空间，而不只是内积空间）。
- **结论**：Riesz 表示定理——在 Hilbert 空间上，每个连续线性泛函都由某个元素的内积给出。完备性是前提，去掉它定理不成立。

同一张卡上常常同时压着这四类。**不标来源，读者判断不出哪条能直接拿去用。**

---

## 6. 命名（当卡需要长期留在库里时）

三段式：`<领域>.<对象>.<限定>`

- 全中文，专名保留原文（人名、标准缩写）。
- **限定段写主张，不写话题**。「概述」「总结」「相关」等于没限定，是 id 的垃圾值。
- **一名多义 = 层级缺失**：当同一个名字下面其实有多种对象时，说明该拆成父卡与子卡，不要硬塞进一张卡。

三个名字各有分工，不能兼任：

| 名字 | 用途 | 谁定 |
|---|---|---|
| 库内 id | 定位、挂树、防撞名 | 用户；你只建议 |
| 引用别名 | 写进论文、别人能顺藤摸到原文 | 学术惯例，你必须给 |
| 口语名 | 对话里指代 | 随语境，不要求唯一 |

命名理由写三行：**为何这样叫 / 挤掉了谁 / 论文里引作**。第二行是对命名空间的声明，防止下次有人起个近义名把卡拆散。

提及文献时**截取标题**（至少五六个词），不要只给作者名；截取必须**越过分叉点**——两个标题前五个词相同的例子并不罕见。文献本身没有给这个对象起名时，才退回作者 + 年份。

---

## 7. 吸收三问（在会话内执行）

吸收判据必须当场用，否则"吸收了没有"无法证伪：

1. 说得出主张和它的条件？
2. 给一个情形，判得出该不该用这张卡？
3. 说得出该由哪张邻近的卡接手？

三问全过才算吸收完成。第 3 问是把知识挂回结构里——没挂上去的知识，几天后会掉。

**凡是需要事后回看才能维持的知识，就是没吸收。** 所以不要指望读者去翻链接。

---

## 8. 卡的会话边界

- 卡在对话内产生、被读、被吸收，然后**结束**。
- **不建目录、不打版本号、不记覆盖进度、不留任何持久层。** 要留存由用户自行提取，那是他的选择；不提取也没有损失。
- 改版由**用户的疑惑**驱动：同 id 重发，附一行"本版因何而改"。
- 跨会话时靠**重建**，不靠引用旧卡：**重建优于对齐**。引用旧卡要维护名字、版本、路径三样东西，而重建只要一句话。

一条推论：**本 skill 内不得出现工具名、本机路径或私有数据。** 一旦出现，它就绑死在某台机器上，别人抄不走——可移植性的判据就是这一条。

---

## 9. 反面清单

- **问答式小卡**：抽掉上下文、只剩一问一答。丢了卡的意义。
- **填表式输出**：每轮摆满所有小节。读者会停止阅读。
- **纯摘要**：没有锚点、没有边界、没有来源标记。摘要无法被复核，也无法被判该不该用。
- **孤岛卡**：没有上下层。它会在下一次被重复造出来。

---

## 10. 未验条款（跑过完整流程之前，不得当作定论）

本 skill 是设计结论的沉淀，不是实验结论。以下三条尚未验证：

- 「跨卡突破口推进」从未完整跑过（只验证过单卡）；
- 「吸收三问」只跑通过一次；
- 「来源标记」与「命名理由」是否该进每一张卡，尚无定论。

使用本 skill 时应当**保留这一节**：它本身就是本 skill 第 5 节要求的来源标记的一个实例。
