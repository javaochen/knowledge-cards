# knowledge-cards

把「学习、研究、实验中产生的知识」落成**自包含的知识卡片**的一份口径（skill）。

它不是模板，是一组判据加一份可选菜单：卡片在对话里产生、被读、被吸收，然后结束——不建目录、不打版本号、不留持久层。

## 文件

| 文件 | 作用 |
|---|---|
| `knowledge-cards/SKILL.md` | 主文件：给模型执行的口径 |
| `DESIGN-NOTES.md` | 次要文件：设计约束清单、每条约束的由来、已被推翻的旧结论、未验条款 |
| `STORAGE-REFERENCE.md` | 参考：存储态文档族的形态、代价与未验项（不参与执行） |

## 用法

把 `knowledge-cards/` 整个目录拷进任何一个 agent 的 skills 目录，例如：

```
<agent-preset>/skills/knowledge-cards/SKILL.md
```

之后当对话涉及学习、研究或实验，且知识应当留成可复用单元时加载它。它改变的是知识的**落地形状**，不改变你原有的教学或协作方式。

## 它解决什么

- **散**：对话说完就散，没有抓手 —— 卡片把可复用的部分固化成单元；
- **换屏**：把知识放进另一个面板/文件，读者得离开对话再回来 —— 卡片在对话流内发射，不换屏；
- **填表**：每轮摆满固定小标题，读者停止阅读 —— 卡片是菜单不是模板；
- **误用**：分不清一条式子是推导结果还是建模约定 —— 卡片要求每条式子标注来源（恒等／约定／假设／结论）。

## 可移植性判据

本 skill 内**不出现任何工具名、本机路径或私有数据**。一旦出现，它就绑死在某一台机器上，别人抄不走——这条就是可移植性的判据。

## 未验条款

这是设计结论的沉淀，不是实验结论。四条尚未验证：

- 「跨卡突破口推进」从未完整跑过（只验证过单卡）；
- 「吸收三问」只跑通过一次；
- 「来源标记」与「命名理由」是否该进每一张卡，尚无定论；
- 存储态文档族从未完整跑过（只有单节骨架），详见 `STORAGE-REFERENCE.md`。

SKILL.md 第 10 节保留着这一声明——它本身就是该 skill 所要求的「来源标记」的一个实例。
