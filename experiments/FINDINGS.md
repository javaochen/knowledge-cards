# 注入实验：SKILL.md 的效果

一次单题、单样本的对照实验，用来观察把 `knowledge-cards/SKILL.md` 作为系统提示词注入后，输出形状发生了什么变化。**这是示例，不是结论。**

## 复现

```bash
# 需要 DEEPSEEK_API_KEY 环境变量
node experiments/deepseek-inject.mjs --compare "你的问题"
```

脚本只从环境变量读密钥，不写盘、不打印；skill 目录内不含任何工具名或本机路径（遵守 G7）。

## 设置

| 项 | 值 |
|---|---|
| 日期 | 2026-10-23 |
| 模型 | `deepseek-chat` |
| 温度 | 0.7 |
| 问题 | 我在学泛函分析，Riesz 表示定理和“有界线性算子”这两个东西老是分不清，帮我理一理。 |
| 变量 | 是否把 `knowledge-cards/SKILL.md` 全文作为 system 提示词 |

原始输出：

- [基线（裸模型）](samples/2026-10-23-baseline.md)
- [实验组（注入 SKILL.md）](samples/2026-10-23-with-skill.md)

## 结果

| 维度 | 基线 | 实验组 |
|---|---|---|
| 形状 | 五个小标题的讲解 | 两张编号卡 + 一条「接点」边 |
| 来源标记 | 无 | 标注「约定／假设／结论／恒等」 |
| 边界 | 混在「混淆点」一节里 | 每张卡单列「边界」 |
| 吸收 | 以“要不要来道例题”收尾 | 末尾执行「自检三问」 |
| 命名理由 | 无 | 有（解释“有界”为何误导） |
| 输入 tokens | 33 | 2107 |
| 输出 tokens | 1046 | 1017 |
| 用时 | 7.9s | 6.6s |

## 观察

1. **注入改变的是落地形状，不只是措辞。**
   实验组主动把「有界是约定/定义」与「Riesz 是结论」分层，并标出前者是后者的前提；基线只是并列讲解。这是 SKILL.md 第 5 节可观察到的直接作用。

2. **它诱发了一处事实错误。**
   实验组写「连续 ⟺ 有界，这条要定义域空间完备之类的常规设定才干净成立」。这是错的：赋范空间上线性算子的有界性与连续性等价，不需要定义域完备。基线没有这个错误。
   一个待验的解释：skill 要求每个节都能说出「条件／边界」的缺失故障模式，模型可能为填满槽位而虚构前提。

3. **成本几乎全在常驻上下文。**
   `SKILL.md` 约 4710 字，每次调用固定多出约 2074 输入 tokens；输出长度基本不变（1046 → 1017）。它买到的是更可判定的组织方式，不是更多信息。

## 局限

- 单次采样，`temperature=0.7`；实验组的错误可能只是一次采样偏差。
- 结构差异（卡、来源标记、边界）由提示词直接诱导，可信度较高；「是否更容易吸收」完全没有验证。
- 基线本身质量不低，本实验不能支持“注入后答案更好”，只能支持“注入后答案形状不同”。

## 待办

- 换 3–5 个领域、每个各跑 2 次，检查「虚构前提」是否复现。
- 若复现，考虑在 SKILL.md 第 9 节反面清单加一条：不得为填满条件／边界而虚构前提，拿不准就留空。
- 对比「证明」与「验证（证明 + 前提 + 探索 + 反例）」两种节名各跑 2 次，看后者是否减少为填槽而虚构前提。
- 与 `DESIGN-NOTES.md` 的 I 节（未验条款）对齐后再决定是否改 skill。
